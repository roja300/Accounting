# Payments

*Date: 11/10/2026* <br>
*Author: Rojaware*<br>

## Overview

Payments page to derive payment functionality.

### Functional Specification (FS)

1. The system should provide a means for importing payments from standard csv formats from banks.
2. The system should display payments in a table.
3. The system should enable filtering payments.
4. The payment import should include information that would allow payments to be associated with work records.
5. The payment import should support information that would allow people to support tax calculation, e.g, total salary earned in a year, bonuses, etc.
   1. This would be comprised of many rows. Each row would include information like how much was received, who paid it, balance after transaction etc.
6. The system should enable deleting imported payments entirely, by specific dates, or by the file in which it was imported.

### Non-functional Specification (NFS)

1. Payments should be a new module in the web service, that follows the same patterns.
2. The import should be performed on the server side.
3. Each row of an import should be validated.

## Notes

- Although the UI will use a table, instead of cards, it should fit in with the rest of the app.
